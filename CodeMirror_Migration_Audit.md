# CodeMirror 6 Migration Audit & Documentation

This document serves as the historical record and technical documentation for the migration of CodeAlive from the legacy "Mirrored Textarea" setup to the **CodeMirror 6** architecture.

---

## 1. Audit Report: Previous vs. Now

### The Legacy Architecture (Mirrored Textarea)
Previously, the editor functioned by layering a transparent `<textarea>` exactly over top of a `<div>` containing highlighted HTML generated by **Prism.js**.
* **What Broke:** 
  * **Cursor Drift:** Browsers render text inside `<textarea>` elements slightly differently than text inside `<div>` elements. This caused the blinking caret to drift horizontally away from the actual text as lines got longer.
  * **Scroll Sync:** Rapid scrolling frequently caused the transparent textarea and the highlighted div beneath it to fall out of alignment.
  * **Manual DOM Injection:** Features like image widgets and line highlights required brittle manual DOM manipulation, injecting literal HTML tags into the code.

### The New Architecture (CodeMirror 6)
The editor now uses the modern **CodeMirror 6** framework.
* **What it Fixed:**
  * **Perfect Alignment:** CodeMirror handles its own virtual DOM rendering. There are no longer two conflicting layers; what you type is exactly what is highlighted.
  * **Robust State Management:** The `EditorState` acts as the "Single Source of Truth."
  * **Atomic Widgets:** Images are now rendered as immutable CM6 Widgets. They are part of the editor state but don't interfere with raw text selection.
  * **Extensibility:** Line highlights now utilize CM6 `StateField` and `Decoration.line()`, making them bulletproof against line wrapping and scrolling.

## 2. Dependencies & Project Scope

### Removed Dependencies
* **Prism.js** (Core, Line-Numbers, Autoloader) — *Removed from `index.html`*
* **Prism Themes** — *Removed from `index.html`*

### New Dependencies (Loaded via ESM)
CodeMirror 6 is strictly modular. Instead of a single heavy script, packages are imported directly into the browser dynamically via `esm.sh`.
* `@codemirror/state` - Core data structures
* `@codemirror/view` - DOM rendering and UI 
* `@codemirror/commands` - Keybinds and history
* `@codemirror/language` & `@codemirror/language-data` - Syntax highlighting
* `@codemirror/search` - Selection matching
* `@codemirror/theme-one-dark` - Base color scheme

> [!TIP]
> **No Build Step Required:** Because we use `https://esm.sh/...`, the frontend remains pure vanilla Javascript (no Webpack or Vite required).

## 3. Detailed File-by-File Changes

### HTML & CSS
* **`templates/index.html`**
  * Removed `#codeArea`, `#code-highlight`, and `#code-highlighted`.
  * Added the unified `#editor-container`.
  * Added global document `click` listener to dismiss the welcome overlay robustly.
* **`static/css/style.css`**
  * Deleted all absolute positioning hacks used to overlap the legacy layers.
  * Added `.cm-editor`, `.cm-scroller`, and `.cm-gutters` overrides to strip away the default CodeMirror gray backgrounds and enforce CodeAlive's pure dark `#0a0c0f` theme.
  * Added `.cm-selectionBackground` to enforce the legacy neon-green text selection.

### Core Architecture
* **`static/editor.js` [NEW/HEAVILY REWRITTEN]**
  * Initializes the `EditorView` and `EditorState`.
  * Manages dynamic language loading using a `Compartment` (allows swapping language highlighting without destroying the editor).
  * Exposes `setReadOnly(isReadOnly)` using a secondary `Compartment`.
  * Contains the `UpdateListener` that detects user typing and triggers detection/UI changes.
* **`static/main.js`**
  * Transformed into a native `type="module"` script.
  * Removed legacy `textarea` listeners. Replaced them with a centralized initialization sequence.
  * Safely fetches the editor document state (`view.state.doc.length`) dynamically for the `beforeunload` unsaved changes warning.
* **`static/dom.js`**
  * Purged the old `codeArea` element reference. 
  * Replaced with `editorContainer` and added a `getView()` bridge to prevent circular ES Module binding issues.

### Features
* **`static/highlights.js`**
  * Rewritten to use CodeMirror `StateField` and `Decoration`.
  * Restored the `COLOR_POOL` array mapping. Multiple highlights cycle through 5 distinct colors dynamically.
  * Highlight coordinates are calculated mathematically using CM6's `view.coordsAtPos()` instead of measuring DOM rects.
* **`static/image-handler.js`**
  * Rewritten to act as a CodeMirror `ViewPlugin` utilizing `MatchDecorator`.
  * Searches the document state for `[image:xyz]` and seamlessly replaces it visually with an interactive HTML Widget button (View Image) without altering the underlying raw code string.
* **`static/detection.js`**
  * Detached from raw DOM keyup events. It now receives the raw code string directly from the CodeMirror `UpdateListener` whenever `docChanged` is true.
  * Retained 100% compatibility with the FastAPI backend.

### Utilities & Routing
* **`static/modes.js`**
  * Replaced `codeArea.readOnly = ...` logic with the new CM6 `setReadOnly()` hook. 
  * Restored the flow that allows editing on shared links (`/s/...`), while appropriately triggering the edit warning banner.
* **`static/actions.js` & `static/codec.js`**
  * Removed raw string `.value` assignments.
  * Read/Write operations now use `view.state.doc.toString()` and `view.dispatch({ changes: ... })` to safely interact with the document.

## 4. Current Status & Known Quirks

* **Bugs**: There are currently **0 known bugs**. All features (sharing, detection, highlighting, image embedding, edit warnings) have been confirmed working.
* **Quirk - Caching**: Because the frontend relies on `import` statements natively, browsers may aggressively cache module files (resulting in `304 Not Modified`). If you make future updates to `dom.js` or `editor.js`, users may need to hard-refresh, or you may need to implement a cache-busting query parameter strategy on the `import` paths in `main.js`.
* **Quirk - Mobile**: CodeMirror 6 handles mobile keyboards much better than standard textareas, but testing heavily on iOS Safari is recommended as virtual keyboards can sometimes trigger unexpected scroll behaviors.
